# InstaAgent Ad Selection Pipeline

This is the full plan for the InstaAgent ad selection pipeline. The current implementation covers Step 1 and Step 2 foundations, paid-ad and organic video vision enrichment for Step 3 and Step 4, Step 5 embeddings via Voyage AI, and ICP clustering for Step 6.

## Goal

Given a product and keyword set, collect paid ads and organic content, analyze the transcripts, cluster repeated ICPs/formats/hooks, and select top examples that InstaAgent can clone and sell to customers.

## MVP Architecture

- Storage: Supabase Postgres as the system of record.
- Paid ads: Apify official `apify/facebook-ads-scraper` actor over Meta Ad Library URLs.
- Organic: 100% Apify. TikTok via `clockworks/tiktok-scraper` (`ingest-tiktok`, follower counts native) and Instagram reels via `data-slayer/instagram-search-reels` (`ingest-instagram`), with Instagram follower counts backfilled by `backfill-ig-followers` (via `apify/instagram-profile-scraper`).
- Media storage: downloaded videos are persisted to the Supabase Storage bucket `ad-videos`, with `storage_video_url` / `storage_thumb_url` recorded on the item tables.
- Vector storage: Supabase `pgvector` `item_embeddings` table for `icp` and `search` embeddings, generated by Voyage AI (`voyage-4-lite` by default).

## Full Data Flow

1. Product/run setup
   - Create a product record with name, category, target market, and notes.
   - Create a pipeline run with target counts, top K, and source config.
   - Use Claude Haiku to generate 3-6 discovery keywords when manual keywords are not supplied.
   - Store keywords plus per-keyword paid ad and organic target allocations. Allocations must add up to the run targets.
   - Log every API request in `source_queries`.

2. Source ingestion
   - Apify paid ads: build a Meta Ad Library keyword URL for each allocated keyword and run `apify/facebook-ads-scraper`.
   - Apify organic: query TikTok (`clockworks/tiktok-scraper`, via `ingest-tiktok`) and Instagram reels (`data-slayer/instagram-search-reels`, via `ingest-instagram`) by allocated keyword.
   - Instagram follower backfill: `backfill-ig-followers` hydrates reel follower counts via `apify/instagram-profile-scraper` (TikTok follower counts are native).
   - If a provider returns fewer items than the keyword target, save the returned items and move on.
   - Store raw payloads and source-shaped candidates in separate Supabase tables:
     - Apify Meta Ad Library paid ads -> `paid_ads`.
     - Apify TikTok/Instagram organic -> `ugc_items`, with stable fields mapped to first-class columns and provider overflow in `source_metrics`.
   - The Apify normalizers recompute `virality_score` / `virality_tier` for organic from engagement metrics, since these providers do not supply a virality score.

3. Transcript extraction
   - Paid ads and organic use the same vision enrichment. Each item's video bytes are downloaded into memory, persisted to the Supabase Storage bucket `ad-videos` (recording `storage_video_url` / `storage_thumb_url` on the item table), and sent base64-encoded in a single OpenRouter vision call (default model `google/gemini-3-flash-preview`); nothing is written to disk.
   - Paid ads: enrichment runs automatically after `ingest-apify-ads` and is available standalone as `enrich-paid-ads`.
   - Organic: enrichment runs automatically after `ingest-tiktok` / `ingest-instagram` and is available standalone as `enrich-ugc`.
   - The model returns the spoken transcript plus creative analysis in one call; the transcript is stored in `item_enrichments`.

4. LLM analysis
   - Both paid ads and organic: analysis comes from the same OpenRouter vision call as transcription. ICP (`persona`), `target_demographic`, `hook`, `content_format`, and the full creative field set are produced for every item.
   - All output is written to one row per item in the polymorphic `item_enrichments` table (`item_type` `paid_ad` | `ugc_item`, `item_id`): `transcript_text` + `transcript_segments`, `ai_description`, the analysis fields, and `analysis_model` / `analyzed_at` bookkeeping. Raw responses go to `raw_payloads`.
   - For paid ads, the existing ad copy is also passed to the model.

5. Embeddings
   - Generate two independent embedding spaces per item from its `item_enrichments` row:
     - `icp` (from `persona` + `target_demographic`; reserved for clustering).
     - `search` (from `ai_description` + a labeled tag block + the full transcript).
   - Do not concatenate these into one blended embedding.
   - Implemented: `embed-items` calls Voyage AI (`POST /v1/embeddings`, batches of 128) and upserts one row per item/space/model into `item_embeddings` (pgvector, 1024 dims), idempotent via a unique constraint. Spaces with no usable text are skipped.

6. Clustering
   - Cluster separately by source on the `icp` embedding space (paid ICP, organic ICP).
   - Store cluster labels, centroids, member distances, and repeatedness counts.
   - Implemented now: `cluster-items` clusters ICP embeddings only (`space = 'icp'`) per source with HDBSCAN, writes assignments to `item_clusters`, writes summaries to `clusters`, and can label clusters through OpenRouter.

7. Selection
   - Paid ads: select top K per cluster by longevity, using `paid_ads.running_duration DESC`.
   - Organic: select top K per cluster by the recomputed `virality_score DESC`.
   - Normalize per ICP so broad ICPs do not dominate.
   - Dedupe exact URLs/source ids first, then near-duplicate transcripts/hooks.

8. Export
   - Export CSV/JSON grouped by run, source, embedding space, cluster, and ICP.
   - Include URL, thumbnail, transcript, metrics, labels, score, why selected, and cloneability notes.

## Current Implementation Scope

Step 1, Step 2, paid-ad and organic vision enrichment for Steps 3 and 4, Step 5 embeddings, and Step 6 ICP clustering are implemented now. Migrations run 001 through 016: 015 added the `search` embedding space, Storage columns, organic enrichment parity, the match RPC, and the `ad-videos` Storage bucket; 016 added `item_enrichments` with a backfill plus the column/table drops.

Included:

- Supabase schema for products, runs, keywords, source query logs, raw payloads, Apify-shaped `paid_ads`, Apify TikTok/Instagram-shaped `ugc_items`, the polymorphic `item_enrichments` table, and API usage.
- CLI to create product/runs and Claude-generated or manual keyword allocations.
- CLI to ingest Apify Meta Ad Library paid ad candidates across stored keyword allocations.
- CLI to ingest Apify TikTok organic (`ingest-tiktok`) and Instagram reel organic (`ingest-instagram`) across stored keyword allocations.
- CLI to backfill Instagram reel follower counts via `apify/instagram-profile-scraper` (`backfill-ig-followers`).
- OpenRouter vision enrichment for both sources: one call per video producing the transcript and creative analysis into one `item_enrichments` row, after downloading the video to memory and persisting it to the `ad-videos` Storage bucket. Auto-run after `ingest-apify-ads` (`enrich-paid-ads`) and after `ingest-tiktok` / `ingest-instagram` (`enrich-ugc`); both also available standalone.
- Voyage AI embeddings: `embed-items` generates `icp` and `search` vectors for enriched paid ads and organic items into the pgvector `item_embeddings` table (migration 013).
- ICP clustering: `cluster-items` clusters `item_embeddings` rows per source with HDBSCAN, writes assignments to `item_clusters`, writes cluster summaries to `clusters`, and optionally labels clusters with OpenRouter (migration 014).
- Semantic search API and search UI frontend over the `search` embedding space.
- Endpoint documentation that matches the ingestion code.

Not included yet:

- Ranking/selection outputs.
- Dedupe.
- Exports.
- Review UI for selection.

## Source Notes

Organic is sourced entirely from Apify: `clockworks/tiktok-scraper` for TikTok and `data-slayer/instagram-search-reels` for Instagram reels, both driven by arbitrary keyword discovery. Neither actor is transcript-native, so transcripts and creative fields come from the shared OpenRouter vision enrichment stage rather than the provider payloads. The `icp` embedding space is reserved for the ICP clustering layer; the `search` space backs semantic search over `ai_description`, the labeled tag block, and the full transcript.
